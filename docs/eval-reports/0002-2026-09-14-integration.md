## Findings

1. **Real idempotency bug found and fixed in the harness's mock pipeline, and very likely present in
   the production workflow too.** The NORMALIZE stage's merge branch (`intake-normalize.js` STEP 3 /
   my `mock-pipeline.mjs` first draft) reported `merged=true` — and so appended a provenance line and
   incremented `duplicatesMerged` — on *every* re-visit of an already-known source, not only when a
   genuinely new source was added. A second pass over an unchanged scratch dir therefore grew
   `provenance-log.md` and inflated `duplicatesMerged` every run, which would fail FR-005/SC-006. The
   mock pipeline now only counts/logs a merge when the source was not already listed. **The
   production prompt for `write-job-record` (STEP 3) has the same "report merged=true whenever this
   branch ran" phrasing and is not yet confirmed to guard the same way** — recommend a follow-up check
   against the real `workflow-tool` substrate before trusting production idempotency here.
2. **`last-run-summary.md` legitimately differs between first and second pass** (it reports *this
   run's* new activity, not a cumulative total), so the original contract wording ("unchanged")
   was imprecise. Corrected to "zero new activity" in `contracts/expected-tree.md` and implemented
   as such in `evals/integration/idempotency.mjs` (checks the returned summary's counters, not a
   byte-diff of the report).
3. **Manual-drop `id`/`sourceRef` cannot use the true absolute filesystem path in a committed
   fixture** — the production prompt's literal instruction (`id=<absolute file path>`) is fine for a
   real run but makes a byte-locked expected tree non-reproducible across scratch locations. The
   synthetic dataset's mock pipeline uses a dataDir-relative portable ref
   (`inputs/manual-postings/<file>`) instead, noted in `mock-pipeline.mjs`. Production behaviour is
   unchanged; this is a fixture-authoring adaptation only.
4. **Board-domain hygiene**: the original settings draft pointed Board B at `boards.example.com`,
   which is IANA-reserved but *does* resolve (unlike `.invalid`, RFC 2606). Changed to
   `boards-b.invalid` before any run.
5. **Scope gap, not a defect**: SC-002's "a fixture reaching the live internet" scenario (point a
   tracked search at a resolving host, confirm the gate fails and names it) could not be exercised
   through the `mock` substrate as literally described, because `mock`'s collect stage is a
   deliberate no-op (research D4/D7 — the dataset is pre-seeded, collect never runs). The
   hermeticity guard (`evals/lib/network-guard.mjs`) was verified directly instead: a `fetch()` call
   during a guarded window throws and is named in the blocked-call list. Full end-to-end validation
   of the "resolving host → caught" path needs a `workflow-tool` substrate run (deferred; no
   live/metered run has occurred yet in this feature).
6. Documentation correction: `contracts/expected-tree.md` and `data-model.md`'s "Expected-output
   tree" section used illustrative paths (`outputs/jobs/`, `outputs/provenance-log.md`) that predate
   the actual implementation (`outputs/job-records/`, root-level `provenance-log.md`). Corrected to
   match the real system under test.

# Tasks: Pipeline Eval Harness

**Input**: Design documents from `/specs/003-eval-harness/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (all present)

**Tests**: This feature *is* a test/eval harness — the "implementation" tasks below build test and
eval code. No separate meta-test layer is generated; each story's own Independent Test is the
verification step and is listed as its final task.

**Organization**: Tasks are grouped by user story (US1–US5) so each layer of the pyramid can be
built, run, and demoed independently.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel — different files, no dependency on an incomplete task
- **[Story]**: US1–US5 (Setup / Foundational / Polish carry no story label)
- Every task names an exact path

## Path Conventions

Single project. Harness under `evals/` at repo root; shared source-of-truth modules under
`.claude/workflows/lib/`; synthetic fixtures under `tests/synthetic/`; evidence under
`docs/eval-reports/`. Paths below are repo-relative.

## Phase 3: User Story 1 — Catch a component defect without a full pipeline run (Priority: P1) 🎯 MVP

inlined-copy region regresses.

**Independent Test**: revert `titleKey`'s `.toLowerCase()`; `npm test` fails naming the case; restore
→ green. Edit one char inside an inlined region → `drift.test.mjs` fails with a diff; revert → green.
No model call, no network.

  `slug`, `stableHash`, `dedupKey` assembly; include as fixtures the known bug-3 (free-text location

  `effectiveExcludedLocations`, `completenessLevel` (the low-completeness threshold rule).

- [ ] T014 [US1] `evals/component/drift.test.mjs` — for each region (`intake-core`, `prompts`): read

- [ ] T015 [US1] Wire the `component` layer into `evals/run.mjs` (delegate to `node --test`, map exit

## Implementation Strategy

### MVP (User Story 1 only)

1. Phase 1 Setup.
2. Phase 2 Foundational — module extraction + re-inline + runner skeleton.
3. Phase 3 US1 — component layer + drift guard.
4. **STOP and validate**: revert a helper, `npm test` fails and names it; revert an inlined char,
   `drift.test.mjs` fails; suite < 5 s, offline. Wireable into pre-commit.

### Incremental delivery

1. Setup + Foundational → shared modules live, workflow re-inlined.
2. + US1 → component regressions caught in seconds (MVP).
3. + US2 → deterministic integration gate + idempotency over the synthetic dataset.
4. + US3 → spend controls and credential hygiene enforced on the metered path.
5. + US4 → per-component evals for the four model-backed subtasks.
6. + US5 → committed evidence + spend ledger, retro-fitted to earlier layers.
7. Polish; then — only on explicit user credit approval — T049 builds the standalone metered
   substrate (the FR-020 decision point).
